# 📊 パフォーマンス改善ガイド

このドキュメントでは、アプリの読み込み速度を改善する方法を説明します。

## 🐌 読み込みが遅い原因

### 1. **データベース内の重複データ**
- 同じ川が複数回登録されている場合、データ取得に時間がかかります
- 重複データが多いほど、ネットワーク転送量も増加します

### 2. **データベースのコールドスタート**
- Supabase無料プランでは、一定期間アクセスがないとデータベースがスリープします
- 初回アクセス時は30秒〜1分程度かかる場合があります

### 3. **大量のデータ取得**
- データベースに登録されている川の数が多い場合、全件取得に時間がかかります

## ✅ 改善方法

### 方法1: 重複データの削除（推奨）

重複データを削除することで、以下の効果が期待できます：
- ✅ データ取得時間の短縮
- ✅ ネットワーク転送量の削減
- ✅ メモリ使用量の削減
- ✅ ブラウザの処理負荷の軽減

#### 手順

1. **重複削除ツールにアクセス**
   ```
   /?test=duplicate-cleaner
   ```

2. **「重複を分析」ボタンをクリック**
   - データベース内の重複データを検出します
   - 重複の件数と詳細が表示されます

3. **重複内容を確認**
   - 各重複グループで、どのデータが保持され、どのデータが削除されるか確認できます
   - ✅ 緑色のカード：保持されるデータ（IDが最も小さいもの）
   - 🗑️ 白いカード：削除されるデータ

4. **「重複を削除」ボタンをクリック**
   - 確認ダイアログが表示されます
   - OKをクリックすると削除が実行されます

5. **結果を確認**
   - 削除件数と残りのデータ数が表示されます
   - 3秒後に自動的に再分析が実行されます

#### 削除されるデータの基準

重複削除ツールは、以下の基準でデータを保持します：

- **グループ化の基準**: 川名 + 都道府県 + 観測所名
- **保持するデータ**: 各グループで最も小さいID（最初に登録されたデータ）
- **削除するデータ**: 上記以外の重複データ

例：
```
グループ1: 多摩川 + 東京都 + 田園調布
  ├─ ID: 1 → ✅ 保持
  ├─ ID: 5 → 🗑️ 削除
  └─ ID: 9 → 🗑️ 削除

グループ2: 利根川 + 群馬県 + 八斗島
  ├─ ID: 2 → ✅ 保持
  └─ ID: 7 → 🗑️ 削除
```

### 方法2: データベースのウォームアップ

初回アクセス時の待機時間を短縮するには：

1. **定期的にアクセス**
   - データベースがスリープしないよう、少なくとも1時間に1回はアクセス
   
2. **事前アクセス**
   - 重要な作業の前に、事前にページを開いておく

3. **有料プランへのアップグレード**
   - Pro プラン以上では、データベースが常時起動状態を維持

### 方法3: フロントエンド側の重複排除

現在、フロントエンド側でも以下の重複排除処理を実行しています：

```typescript
// 川名 + 都道府県でユニーク化
const uniqueKey = `${river.name}|${river.prefecture}`;
```

しかし、この処理は以下の理由で十分ではありません：
- ❌ データ取得時のネットワーク転送量は削減されない
- ❌ サーバー側の処理負荷は軽減されない
- ⚠️ 一時的な解決策に過ぎない

**推奨**: フロントエンド側の重複排除に頼らず、データベースから重複を削除しましょう。

## 📊 パフォーマンス測定

### 現在のデータ量を確認

ブラウザのコンソール（F12）を開いて、以下の情報を確認できます：

```javascript
✅ 川データ取得成功
📊 取得した川の総数: 500件
✅ 重複排除後の川の数: 350件
📊 削除された重複データ: 150件
```

### 期待される改善効果

重複データの削除前後で、以下のような改善が期待できます：

| 項目 | 削除前 | 削除後 | 改善率 |
|------|--------|--------|--------|
| データ取得時間 | 5秒 | 2秒 | 60%短縮 |
| 転送データ量 | 2MB | 1MB | 50%削減 |
| 初回レンダリング | 3秒 | 1秒 | 67%短縮 |

※ 実際の効果は、重複データの量によって異なります。

## 🔧 トラブルシューティング

### Q: 重複削除後もまだ遅い

**A: 以下を確認してください：**

1. **データベースのコールドスタート**
   - `/?test=connection-test` でデータベースの状態を確認
   - スキーマキャッシュエラーが出ている場合は、1〜2分待ってから再度アクセス

2. **ネットワーク速度**
   - ブラウザの開発者ツール（F12）→ Networkタブで転送速度を確認
   - 遅い場合は、ネットワーク接続を確認

3. **データ量**
   - 現在のデータ数を確認（コンソールに表示されます）
   - 300件以上の場合は、さらなる最適化が必要かもしれません

### Q: 重複削除ツールでエラーが出る

**A: 以下を試してください：**

1. **ブラウザのコンソールでエラー詳細を確認**
   - F12キーを押してコンソールを開く
   - 赤いエラーメッセージを確認

2. **データベース接続を確認**
   - `/?test=connection-test` でサーバー接続をテスト

3. **時間をおいて再試行**
   - データベースが起動中の場合、1〜2分待ってから再度実行

### Q: 削除してはいけないデータが削除されそう

**A: 安心してください：**

1. **削除前に確認できます**
   - 「重複を分析」で削除対象のデータを事前に確認できます
   - 各グループで保持されるデータと削除されるデータが明確に表示されます

2. **ID順で保持**
   - 最も小さいID（最初に登録されたデータ）が保持されます
   - 通常、最初に登録されたデータが最も信頼性が高いです

3. **削除は確認後に実行**
   - 確認ダイアログで最終確認があります
   - キャンセルすれば削除されません

## 💡 ベストプラクティス

### 定期的なメンテナンス

1. **月1回の重複チェック**
   - データを追加した後は、重複削除ツールで確認
   
2. **データ追加時の注意**
   - CSV一括登録時は、事前に重複をチェック
   - 手動登録時は、既存データを検索してから追加

3. **パフォーマンスモニタリング**
   - ブラウザのコンソールで読み込み時間を確認
   - 遅くなってきたら重複削除を実行

### データ品質の維持

1. **正確なデータ登録**
   - 川名、都道府県、観測所名を正確に入力
   - 余分なスペースや記号は避ける

2. **一貫性のある命名**
   - 同じ川は同じ名前で登録（「多摩川」と「玉川」は別物として扱われます）
   
3. **定期的なデータ検証**
   - `/?test=duplicate-analyzer` で重複パターンを分析
   - 問題があれば早めに対処
